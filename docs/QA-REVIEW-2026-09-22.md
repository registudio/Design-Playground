## Confirmed findings

### High — registry selections do not render in the composed sample

`src/preview/surfaces/SamplePage.tsx:80` outputs a text list of external selections and source links. Only authored originals use live iframes. The visualise step therefore does not show everything selected or honor external element placement visually. This contradicts the intended end-to-end flow.

### High — the all-element audit does not test actual rendering

`scripts/audit-element-previews.mjs` fetches HTML and checks status and an old error phrase. It never mounts a browser component or examines runtime failures, blank canvases or dimensions. Generated fallback documents can pass. Previous statements that all 436 previews rendered successfully were stronger than this evidence supports.

### Medium — preview failures can be absent from the export report

`src/components/RegistryPreview.tsx` changes local status to failed after 15 seconds but does not write that timeout to `previewStatuses`. `src/export/quality-report.ts` reads only that map. A timed-out card may be exported as unobserved or with a previous observation. Status records also omit the variant and observation time, so they cannot establish freshness for a changed variant.

### Medium — export dialog lacks Escape dismissal and focus containment

Live reproduction: open Export project, focus Close, press Escape; the dialog remains open. The component sets modal ARIA attributes but has no Escape handler or focus trap. Keyboard users can navigate outside the apparent modal.

### Medium — mobile sample navigation disappears

At phone preview width, the sample's Services/Work/About/Contact navigation links disappear. `app/preview/preview.css:494` hides `.dp-navbar-links`; the observed sample presents no replacement menu control. The call-to-action remains, but section navigation is unavailable.

### Medium — quality report does not identify concrete missing packages

`src/export/quality-report.ts` lists installation commands and declared animation engines, but not each selected component's complete npm dependencies or specific missing packages. It explicitly says target installation is unverified, which is honest, but the requested missing-dependency report is only partially implemented. Cost classification excludes authored effects and unclassified WebGL dependencies.

### Medium — progress is visit history rather than persistent setup progress

`app/page.tsx` keeps visited steps in component state. Reloading clears the visit markers, and merely opening a step marks it with a tick. The text correctly says unvisited, but it does not indicate which choices are configured, deliberately skipped, or still need review.

### Low — lightweight collection has no meaningful cost filter

`src/components/ElementLibrary.tsx` admits originals when the runtime string contains CSS, including CSS + JavaScript effects. This label is not supported by profiling or a curated low-cost allowlist. Mobile starting points similarly uses category rules rather than per-element device validation.

## Content and UX opportunities

- The sample includes fictional trust claims, client names and prices (for example “Trusted by 200+ teams”). Make their sample status obvious in the export handoff and flag them for replacement.
- “Motion & engines” and copy about connecting libraries remain despite engine selection now being automatic.
- Phone Elements has duplicate step navigation and a 127.5px progress panel; the first actual card starts below the initial screen. A collapsible progress summary and consolidated filters would expose previews sooner.
- One search result is labelled “1 elements to explore.”

## Recommended repair order

1. Render external selections in the sample and create a real browser render audit.
2. Correct preview failure reporting and complete dependency reporting.
3. Fix modal keyboard behavior and mobile sample navigation.
4. Persist meaningful progress, tighten collection labels and reduce phone control density.

## Verification limits

The three-second target is not verified catalogue-wide. The warmup script precompiles eight curated entries only. Successful tests/build and an HTTP preview response do not prove every element is visually correct. Snapshot restore, custom asset upload, drag reorder on touch hardware and actual ZIP download were not exercised in this review.
