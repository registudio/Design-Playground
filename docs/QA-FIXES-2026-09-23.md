# QA fixes and library additions

## Implemented

- Filters are divided into labelled type, source/runtime, and collection groups. Selection controls and reset live in a separate action row. Phone filters start collapsed.
- Nine authored carousel designs and seven authored gallery/media designs occupy distinct categories. Existing external registry items remain available, so the combined category totals exceed these curated counts.
- Motion.dev spring, Lenis scroll, and Vanta NET demos use the actual libraries. Attribution identifies Playground as the demo author and links to the runtime source. These are curated demonstrations, not imports of every example on those websites.
- `predev` and `prebuild` generate separate local bundles. No CDN fetch is needed to start these three demos. Vanta uses compatible Three.js r134; reduced motion or unavailable WebGL produces an explicitly identified static scene.
- Every card has an expand action. Authored and registry previews use a viewport-sized dialog. Background card runtimes are paused while an expanded preview is open.
- ZIP and standalone HTML export embed the selected authored engine runtimes. ZIP includes engine license notices. Export fails explicitly if required engine assets cannot be included.
- Composed samples display external registry previews in their assigned positions. The preview stylesheet now reserves their height and presents loading/error status.
- Export quality reports use variant-specific status keys, observation timestamps, stale markers, package dependencies, and a cost heuristic that includes authored effects and detected WebGL usage.
- Export dialogs support Escape and keyboard focus containment. Mobile sample navigation links target sections that actually exist.
- Project progress stores deliberate reviewed/skipped decisions in the project, survives reload, and participates in undo/history. Visiting a page no longer means completion.
- Collection labels now describe actual filtering: CSS-only originals and Text & feedback originals. Single results use “1 element”. Sample names, prices and claims are labelled as demonstration content.
- The HTTP audit treats generated replacements as failures and no longer calls returned HTML proof of rendering. `npm run audit:render` supplies a browser runtime audit with timings, errors, and screenshots for review.

## Verification and limits

- TypeScript passes; 505 tests pass across 23 test files. Production build passes with the existing dynamic snapshot-file tracing warning.
- Browser checks cover curated category counts, a carousel advancing, viewport-sized dialogs, real Vanta rendering, Motion initialization, Lenis scrolling between chapters, and external SwipeRow rendering in the composed sample.
- At 390×844 and 768×1024, no horizontal page overflow was observed. Phone filters start collapsed. The mobile sample menu appears; Export dismisses with Escape. Temporary viewport and preview device settings were restored.
- The render audit is available as a repeatable script; a complete catalogue browser audit is not claimed in this task.
- Ready is a runtime heuristic, not a guarantee that an upstream component looks correct. Generated replacements and blank/error statuses remain explicit.
- The three-second target is not certified for all 436 external registry entries. Their network dependencies, runtime assumptions and graphics requirements can still affect startup.
- External registry selections in standalone static exports remain installation handoff entries; their live composed previews run in the app. The new authored engine demos are embedded in exports.
- Required packages are listed; whether they are installed in an unrelated destination project cannot be established by this export alone.
